# ADR-006: Sonnet 5.5 builds, Opus 5.5 reviews, Haiku 5.5 judges

**Status:** Accepted (2026-11-15)
**Decision area:** D6, models

## Context

Prices on the Anthropic API, per million input/output tokens: Haiku 5.5 $0.10/$0.50, Sonnet 5.5
$2/$10, Opus 5.5 $4/$20. In A2, Sonnet 5.5 at medium effort solved all three tinydb tasks in
both conditions, so it is good enough for small, well-specified changes in this repo. Agent
sessions are mostly input tokens (files read, tool results), so price differences add up fast
once there are retries.

The reviewer is the one place where a *different* model is worth more than just raw ability.
If the reviewer and the implementer are the same model, they have the same blind spots, and
the reviewer is more likely to find the implementer's reasoning convincing.

## Decision

| Role | Model | Effort | Max turns | Max USD per call |
|---|---|---|---|---|
| Planner (spec, design) | `claude-sonnet-5-5` | high | 30 | 1.50 |
| Implementer | `claude-sonnet-5-5` | medium | 40 | 2.00 |
| Tester | `claude-sonnet-5-5` | medium | 30 | 1.50 |
| Reviewer | `claude-opus-5-5` | high | 40 | 3.00 |
| Testability judge | `claude-haiku-5-5` | low | 1 (no tools) | 0.05 |

Whole-run limit: 8 USD per workflow run (the sum of `total_cost_usd`). If the next step would
go over it, the orchestrator stops and writes why into the current artifact.

## Alternatives considered

- **Opus for everything.** About twice the price per token. For small changes with a clear
  design it's not obvious that it helps, and retries make the cost hard to predict.
- **Haiku for implementing and testing.** Cheapest, but every failed attempt costs a whole
  test cycle, and a few failures would eat the savings.
- **Same model for reviewer and implementer.** Cheaper (Sonnet), but no model diversity.
  Experiment A changes what the reviewer *sees*, not which model it is, so the value of
  model diversity stays an untested assumption (see Limitations).

## Consequences

- The reviewer is the most expensive single call, so I sized the seeded-PR experiments to fit
  the budget.
- Model IDs and limits live in `.autose/config.toml`, so a variant can swap them without
  touching the code.
