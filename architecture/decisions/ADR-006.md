# ADR-006: Sonnet 5.5 for the builders, Opus 5.5 for the reviewer, Haiku 5.5 for the judge

**Status:** Accepted (2026-11-15)
**Decision area:** D6, models

## Context

Prices (Anthropic API, per million input/output tokens): Haiku 5.5 $0.10/$0.50, Sonnet 5.5
$2/$10, Opus 5.5 $4/$20. In A2, Sonnet 5.5 at medium effort solved all three tinydb tasks
under both conditions, so it is capable enough for small, well-specified changes in this
repository. Agent sessions are dominated by input tokens (files read, tool results), so
price differences multiply quickly over retries.

The reviewer is the one place where a *different* model has value beyond ability: if
reviewer and implementer share a model, they share blind spots, and the reviewer is more
likely to find the implementer's reasoning convincing.

## Decision

| Role | Model | Effort | Max turns | Max USD per call |
|---|---|---|---|---|
| Planner (spec, design) | `claude-sonnet-5-5` | high | 30 | 1.50 |
| Implementer | `claude-sonnet-5-5` | medium | 40 | 2.00 |
| Tester | `claude-sonnet-5-5` | medium | 30 | 1.50 |
| Reviewer | `claude-opus-5-5` | high | 40 | 3.00 |
| Testability judge | `claude-haiku-5-5` | low | 1 (no tools) | 0.05 |

Run-level cap: 8 USD per workflow run (summed `total_cost_usd`); the orchestrator stops
with an explanation in the current artifact when the cap would be exceeded.

## Alternatives considered

- **Opus everywhere.** About twice the cost per token; for small changes with an explicit
  design the gain is unclear, and retries make the cost unpredictable.
- **Haiku for implementation and tests.** Cheapest, but a failed attempt costs a whole
  test cycle; a few failures cancel the savings.
- **Same model for reviewer and implementer.** Cheaper (Sonnet), but loses model diversity.
  Experiment A varies the reviewer's *context* rather than its model, so model diversity
  stays an untested assumption (see Limitations).

## Consequences

- The reviewer is the most expensive single call; seeded-PR experiments are sized to fit
  the budget.
- Model IDs and limits live in `.autose/config.toml`, so a variant can swap them without a
  code change.
