# ADR-005: Agents use the SDK's built-in tools behind a per-role permission hook; only non-agent code talks to GitHub

**Status:** Accepted (2026-11-15). **The Bash sandbox point is superseded by
[ADR-011](ADR-011.md)** (2026-11-15): the SDK sandbox did not start on the runner, so agent
Bash now runs in our own bubblewrap jail. The superseded lines are kept below and marked.
**Decision area:** D5, tools

## Context

Agents need to read the repo, and some need to edit files and run tests. But nothing in the six
stages needs an *agent* to talk to GitHub: pushing, opening a PR and posting a review are all
mechanical. And every tool an agent has is also a tool that a prompt injection can use.

## Decision

- Agents run on the **Claude Agent SDK** (`claude-agent-sdk` 0.2.182) with its built-in tools.
  Each role's tools are fixed with `ClaudeAgentOptions.tools`:

  | Role | Tools |
  |---|---|
  | Planner | Read, Glob, Grep |
  | Implementer | Read, Glob, Grep, Edit, Write, Bash |
  | Tester | Read, Glob, Grep, Edit, Write, Bash |
  | Reviewer | Read, Glob, Grep, Bash, Write |

- A **`PreToolUse` hook** (`policy.py`, `on_failure="block"`) approves or denies every single
  tool call:
  - Read/Glob/Grep: only inside the work folder, never inside `.git/`.
  - Edit/Write: the implementer only on paths listed in `design.md` that are outside `tests/`,
    `.github/` and `.autose/`; the tester only on `tests/test_autose_issue_N.py`; the reviewer
    only inside its scratch folder.
  - Bash: each role has an allowlist of command prefixes (`python -m pytest`,
    `python -m compileall`, `git diff`, `git status`, `ls`, …). No pipes to the network, no
    `git push`, no `curl`. ~~Bash runs in the SDK **sandbox** (bubblewrap) with no network
    access.~~ *(Superseded by ADR-011: every allowed command is wrapped in our own bubblewrap
    jail with no network.)*
  - Anything else: denied. `permission_mode="dontAsk"` makes any call the hook didn't approve
    fail instead of asking.
- `setting_sources=[]`, so settings files in the checked-out repo can't add tools, hooks or
  permissions.
- **No MCP servers, no WebFetch or WebSearch.**
- **GitHub is only reached through the `gh` CLI**, called by `gate.py`, the release step of
  `orchestrator.py`, `store.py` and `publish.py`. They pass the job's `GITHUB_TOKEN` to those
  subprocesses explicitly. The token is removed from `os.environ` before any agent starts,
  and `actions/checkout` runs with `persist-credentials: false`.

## Alternatives considered

- **Give agents the GitHub MCP server.** Popular, but it puts a token that can write inside the
  agent process and adds dozens of tools I'd then have to filter.
- **Only use the `can_use_tool` callback.** It isn't asked about calls the CLI already treats
  as safe (reads), so limiting reads to certain paths wouldn't work. The hook sees every call.
- **No Bash at all.** Then the implementer and tester couldn't run tests. "The code builds" and
  "the tests pass" would only be checked after the agent finished, so every mistake would cost
  a whole extra round.

## Consequences

- The policy is about 150 lines of code, and I can unit-test it without a model.
- Agents sometimes waste turns on commands that get denied. Every denial is logged and counted
  per run.
- ~~Sandboxing depends on bubblewrap and unprivileged user namespaces on the runner (Ubuntu
  24.04 needs one `sysctl`). If the sandbox cannot start, the run stops rather than running
  Bash unsandboxed.~~ *(Superseded by ADR-011: the workflow probes `bwrap` before the
  orchestrator starts; if `bwrap` can't run, commands fall back to `unshare -rn`, which still
  has no network, and the log says so.)*
