# ADR-004: State lives on an orphan `autose-artifacts` branch; the work branch holds only code

**Status:** Accepted (2026-11-15)
**Decision area:** D4, state

## Context

State must survive (a) between stages inside a run, (b) between runs, because every review
round is a new workflow run (ADR-002), and (c) a restart of a failed job. Artifacts must also
be readable by anyone following a run on GitHub. Options are files on the PR branch, PR
comments, workflow artifacts, the Actions cache, or a separate branch.

## Decision

- **Within a run:** files in the job workspace (`$RUNNER_TEMP/autose/out`).
- **Durable store:** an orphan branch `autose-artifacts` with
  `issue-N/run-<run_id>-<attempt>/` (all six artifacts plus agent logs and metrics) and
  `issue-N/state.json` (current round, attempt counters, PR number, base commit, cumulative
  tokens and cost). `store.py` pushes with a fetch-rebase-retry loop, because runs for
  different issues may push at the same time.
- **Secondary copy:** every job uploads its outputs with `actions/upload-artifact`, so each
  Actions run page links to them.
- **Human-facing summary:** PR body (`pr.md`), the posted review, and a final
  `MERGE_READINESS_CHECK` comment.
- **Never on the work branch.** `autose/issue-N` contains only the code and test change, so
  merging it does not merge bot artifacts, and the reviewer, who reads the repository at the
  PR head, cannot see `spec.md`, `design.md` or notes.

**Restart semantics.** A re-run of a failed job keeps the same `run_id`; the orchestrator
finds `run-<run_id>-*` in the store and resumes after the last stage whose check passed. A new
`/autose` command gets a new `run_id`, starts from stage 1 and resets the work branch to `main`.

## Alternatives considered

- **Artifacts committed on the PR branch.** Simple and visible, but pollutes the merge and
  breaks reviewer isolation.
- **Only workflow artifacts.** Expire after 90 days, need a login to download, and a later
  run cannot easily read an earlier run's artifacts.
- **Actions cache.** Evictable, not browsable, keyed by exact strings. Wrong tool for audit data.
- **Hidden JSON in PR comments.** Readable by later runs, but awkward to update and mixes
  machine state into the conversation.

## Consequences

- One extra branch in the fork; it is never merged.
- Store pushes need `contents: write`, so the jobs that write state have it and the
  reviewer job does not.
- `runs.md` can link straight to `tree/autose-artifacts/issue-N/...`.
