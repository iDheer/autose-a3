# ADR-004: State lives on a separate `autose-artifacts` branch; the work branch only has code

**Status:** Accepted (2026-11-15)
**Decision area:** D4, state

## Context

State has to survive three things: moving between stages inside a run; moving between runs,
since every review round is a new workflow run (ADR-002); and re-running a failed job. The
artifacts also have to be readable by anyone following a run on GitHub. The options were files
on the PR branch, PR comments, workflow artifacts, the Actions cache, or a separate branch.

## Decision

- **During a run:** plain files in the job's workspace (`$RUNNER_TEMP/autose/out`).
- **Long-term store:** an orphan branch called `autose-artifacts`, with one folder per run,
  `issue-N/run-<run_id>-<attempt>/` (all six artifacts plus agent logs and metrics), and one
  `issue-N/state.json` per issue (current round, attempt counters, PR number, base commit,
  total tokens and cost). `store.py` pushes with a fetch, rebase and retry loop, because runs
  for different issues can push at the same moment.
- **Backup copy:** every job also uploads its outputs with `actions/upload-artifact`, so each
  Actions run page links to them.
- **For people:** the PR body (`pr.md`), the posted review, and a final
  `MERGE_READINESS_CHECK` comment.
- **Never on the work branch.** `autose/issue-N` only holds the code and test change. That way,
  merging it doesn't merge bot files, and the reviewer, who reads the repo at the PR head,
  can't see `spec.md`, `design.md` or any notes.

**Restarts.** Re-running a failed job keeps the same `run_id`. The orchestrator finds
`run-<run_id>-*` in the store and carries on after the last stage whose check passed. A new
`/autose` command gets a new `run_id`, starts again from stage 1, and resets the work branch to
`main`.

## Alternatives considered

- **Commit artifacts to the PR branch.** Simple and visible, but they'd end up in the merge,
  and the reviewer would see them.
- **Only workflow artifacts.** They expire after 90 days, need a login to download, and a later
  run can't easily read an earlier run's artifacts.
- **Actions cache.** Entries can be evicted, can't be browsed, and are looked up by exact keys.
  The wrong tool for an audit trail.
- **Hidden JSON inside PR comments.** Later runs could read it, but it's awkward to update and
  mixes machine state into the human conversation.

## Consequences

- The fork gets one extra branch, which is never merged.
- Pushing to the store needs `contents: write`, so the jobs that save state have it and the
  reviewer job doesn't.
- `runs.md` can link straight to `tree/autose-artifacts/issue-N/...`.
